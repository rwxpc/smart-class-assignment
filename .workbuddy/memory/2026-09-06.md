## 分班卡死修复（调整班级数后无法完成）
- 现象：runstate 卡在 status=running（进度89%），前端收到 409 后每 3 秒无限重试"等待释放锁"→ 永远无法完成
- 根因：批次中途服务器被杀/崩溃（或 runOnce 抛异常），status='running' 被永久写入磁盘；后续所有 start 全被 409 拦截
- 修复（server.js start 分支）三层：
  1. 自愈：running 且心跳超 5 分钟（或无心跳）→ 自动复位 idle 继续接力（保留进度）
  2. 兜底：runOnce 用 try/catch 包裹，异常时状态置 error/清零并返回 500，绝不让 running 卡死
  3. 班级数变更检测：st.class_num ≠ config.class_num → 重置 completed_runs/best_result（旧分配是新班级号无效数据）
- runstate 新增 heartbeat 字段；本机 curl 测试需 --noproxy "*"（系统代理会把 localhost 请求变成 502）
- 后台启动服务器必须用 run_in_background 参数（子 shell & 会在命令结束后被清理杀掉）

## 人数均衡修复（各班人数差≤1）
- 用户要求各班总人数差不超过 1；此前 400人÷7班 人数极差达 4~6
- 根因链（三个叠加问题）：
  1. 蛇形初始化按"每段每班一个原子"分配，绑定组是大原子（2人），取模分配导致人数失衡 → 改为"优先分给当前人数最少的班（同分按蛇形顺序轮转）"
  2. 2-opt 交换不同大小的原子会改变班级人数，但 classCost 没有人数项 → 加 `dev^2 * 2` 人数偏离代价（ctx.totalN/classNum 为理想值）
  3. 互斥约束逻辑系统性写反（严重）：互斥组=组员必须分在不同班，同班才是冲突。但 countViol/repairExcludes 把"跨多班"当冲突去修、把"同班"当正常跳过；excludeOkForSwap 又会误拒合法的修复交换（换出后原班残留的组员被当冲突）→ 全部按"组内同班成员数≥2 才是冲突"修正
  - 上一轮会话"互斥冲突 0"的结论是测试脚本口径反了（把跨班当违规统计），实际一直有 3~5 个真实冲突，本次已修正
- 修复后实测（400人、7种子、4种模式）：人数极差≤1、男女极差≤1、总分偏离≤0.05、互斥冲突 0、绑定拆散 0、cost 21.1、单轮约 1s
- 验证互斥时正确口径：组员分不同班=满足；同班=冲突（cs.size < n 才算冲突）
